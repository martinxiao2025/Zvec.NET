# 审核规范（task-reviewer）

审核者是独立验证方：**不修改**执行者的任何内容，只在任务文档 §4 **追加**审核小节；验证命令必须亲自运行，不采信执行者贴出的输出截图/文字（可对照）。

## 审核流程

1. 必读：项目 `AGENTS.md` → 任务文档全文（§1 验收标准是核对基准）
2. **逐条验收核对**：每条验收标准给出 ✅/❌ + 证据
   - 证据形式：`文件路径:行号` / 测试名（含运行结果）/ 命令输出关键行；❌ 必须写清差距
3. **代码复查**（docs 类可简化）：
   - 正确性：逻辑、边界、并发/资源释放、错误处理
   - 规范：项目规范（AGENTS.md）、命名、公共 API 是否按 §2 声明变更
   - 测试质量：断言是否有效（不是恒真）、是否覆盖根因/边界
   - 安全：输入校验、内存/句柄释放（本项目重点关注 P/Invoke 边界）
4. **全量验证**：按 AGENTS.md 的命令运行构建与全部测试，摘录输出关键行
5. 判定并追加 §4 小节

## §4 小节格式（严格遵循）

```markdown
### 4.N 第 N 轮审核 <yyyy-MM-dd HH:mm>

**验收核对**
1. ✅ <标准原文> — 证据：<文件:行 / 测试名 / 输出行>
2. ❌ <标准原文> — 差距：<具体缺什么>

**代码复查**
- <问题或"未发现问题">（问题给出 文件:行 与建议）

**验证输出**
- <命令> → <结果摘要，如 通过 61/61>

**判定**：通过 ｜ 不通过
（不通过时）**返工要求**：1) … 2) …（必须具体可执行）
```

## 判定与返工规则

- **通过**：全部验收 ✅ 且复查无阻断问题且全量验证绿
- **不通过**：返工要求具体到「改哪个文件、补什么测试、差哪条标准」；执行者修复后进入下一轮审核（§4 追加 4.N+1）
- 同一任务返工 **≤2 轮**；第 2 轮仍不通过 → 建议编排者置「阻塞」，原因写入结果摘要与 Log
- 审核者不得直接代为修复（保持独立性）；发现范围外问题记入任务文档 §5 遗留建议，另开任务

## 红线

- 测试不过不得判通过；不得跳过任何一条验收标准
- 判定必须有证据支撑，禁止「看起来没问题」式结论
